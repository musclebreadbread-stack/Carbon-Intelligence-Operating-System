## 1. 설계 원칙

1. **순수 도메인 계층 + 얇은 영속화 껍데기.** 모든 계산 로직은 `src/lib/domain`, `src/lib/core`,
   `src/lib/reference`, `src/lib/ai`에 있으며 `@prisma/client`, `next/*`, `@supabase/*`를 **하나도**
   import하지 않습니다(grep으로 검증). 개발 환경에 접속 가능한 데이터베이스가 없었기 때문에, 계산
   엔진을 실제로 검증할 수 있는 유일한 방법이었고 동시에 산정 로직의 재현성을 보장합니다.
2. **데모 모드.** 데이터베이스가 없거나 연결 불가일 때 조회는 내장 픽스처로 대체되고, 쓰기는
   `DEMO_MODE`로 거부됩니다. 픽스처는 **실제 엔진**에 입력되므로 화면의 모든 수치는 계산된 값이며,
   시드 데이터가 동일하기 때문에 데이터베이스를 연결해도 숫자가 바뀌지 않고 저장만 가능해집니다.
3. **통계 AI는 실제 계산, 생성형 AI는 서술.** 이상 탐지·예측·데이터 공백·신뢰도는 결정론적 통계로
   구현했고, 언어모델은 그 수치 위에 사람이 읽을 문장을 붙이는 역할만 합니다. 감사 대상 숫자는 항상
   재현 가능합니다.
4. **불확실성은 시드 고정 난수(mulberry32)로 계산**하므로 몬테카를로 결과가 실행마다 동일합니다.

## 2. 단계별 구현 내역

### 0단계 — 기반 (항목 1~5)
- Vitest 도입(`npm test`), 타입 검사·시드·문서 생성 스크립트 정비.
- 베이스라인 마이그레이션 `prisma/migrations/0_init`을 `prisma migrate diff`로 오프라인 생성(라이브 DB 없이 148개 모델 전체 DDL).
- 공용 원시 계층: `Result`/`AppError` 체계, 반올림·통계 헬퍼, 회계연도·기간 계산.
- 참조 데이터: AR4/AR5/AR6 GWP 표, 단위 레지스트리와 환산 계수, Scope 3 15개 카테고리 카탈로그, 11개 공시 프레임워크.
- 단위 환산(직접·역·1홉 피벗)과 GWP 정규화(바이오제닉 CO2 분리).

### 1단계 — 배출량 산정 엔진 (항목 6~13)
- **계수 해석**: 유효기간·활성 여부·특이성 순위(조직 > 공급자 > 국가 > 지역 > 전역)로 계수를 선택하고 선택 근거를 문자열 배열로 남깁니다.
- **Scope 1**: 고정연소·이동연소·공정·탈루(냉매 스크리닝 및 물질수지) — 각 결과에 계산 추적(수식·입력·출력·단위) 포함.
- **Scope 2**: 위치기준·시장기준 이중 보고, 계약수단 적용 순서(공급자 특정 → REC/GO → 잔여 믹스), 과다 REC의 음수 배출 방지.
- **Scope 3**: 15개 카테고리 전부 개별 함수 + 디스패처, 지출기반·활동기반·공급자특정·하이브리드 접근법 지원.
- **집계**: 인벤토리 산출, 7단계 계층 롤업, 연결 방식(운영통제·재무통제·지분율), 집약도(매출·생산량·면적·인원), 배분(물리·경제·질량·에너지).
- **불확실성**: 오차 전파(제곱합근)와 몬테카를로(시드 고정, 신뢰구간).
- **데이터 품질**: 완전성·정확성·시간적합성·일관성·신뢰성 5개 차원 점수와 등급 판정.
- **오케스트레이터**: 활동자료 → 계수 해석 → 단위 환산 → 스코프별 계산 → 품질 점수 → 집계 → 불확실성 → 추적·계보까지 한 번에 수행.

### 2단계 — 규칙·계보·감사 (항목 14~16)
- 규칙 엔진: 13개 연산자, AND/OR 논리 그룹, 우선순위, 6종 액션(플래그·거부·필드설정·통지·재계산·배정)을 부수효과 없는 효과 목록으로 반환.
- 데이터 계보: 노드·엣지 그래프, 상·하류 추적(순환 방지), 출처 트리, 변환 기록 부착.
- 감사 추적: 필드 단위 diff(비밀 필드 자동 `[REDACTED]`), 증빙 SHA-256 해시.

### 3단계 — 목표·시나리오·재무·공시·검증 (항목 17~22)
- SBTi: 절대감축 경로(1.5°C 연 4.2%), 부문별 탈탄소 경로, 진척 평가, 넷제로 잔여배출·중화량, 적격성 경고(기준연도 최신성, 최소 야심, Scope 3 40% 임계).
- 시나리오: 9종 시나리오 타입별 기본 레버(성장률·에너지효율·재생에너지 비중·연료전환·공급망·탄소가격), 시나리오 비교, 탄소예산 소진·초과 연도.
- 재무: NPV·IRR(이분법)·회수기간·ROI·감축단가, MACC 곡선과 최소비용 포트폴리오 선택, 감축 로드맵과 잔여 격차.
- 탄소금융: 크레딧 잔량, FIFO 빈티지 상각, 총배출/순배출 분리, 만료 임박 크레딧, 시가평가, 내부탄소가격, ETS 포지션, REC/PPA 커버리지.
- 공시: CDP·ISSB·ESRS E1·TCFD·GRI 305·SASB 요구사항 카탈로그, 인벤토리 자동 매핑, 완성도와 필수 미응답 목록, 보고서 섹션 조립.
- MRV·검증: 중요성 판정과 오기재 누적에 따른 의견 유형(적정·한정·부적정), 발견사항 심각도 롤업, 검증 준비도, 모니터링 계획 커버리지, 측정 주기 기반 완전성, 증빙 패키지.

### 4단계 — AI (항목 23~28)
- LLM 추상화: `LlmClient` 인터페이스, OpenAI 클라이언트(fetch·타임아웃·재시도·오류 매핑), 결정론적 클라이언트, 환경변수 기반 팩토리.
- 통계 AI: 이상 탐지, 예측, 데이터 공백 탐지·추정, 신뢰도 점수.
- 설명 가능 AI: 계산 추적을 단계별 설명·가정 기록으로 조립.
- 에이전트 런타임: 도구 레지스트리, 반복·토큰 상한이 있는 실행 루프, 대화 윈도잉, MCP 클라이언트.

### 5단계 — 영속화·보안·API (항목 29~34)
- zod 검증 스키마(Prisma 열거형에서 파생), 저장소 계층(`withDb` 폴백 + 일관된 데모 픽스처).
- 세션 해석, RBAC/ABAC 인가, AES-256-GCM 필드 암호화.
- 14개 서버 액션 모듈: 인증 재확인 → 검증 → 도메인 호출 → 저장 → 감사 기록, 데모 모드 거부.
- 12개 REST 엔드포인트(`/api/v1/*`): API 키 인증, 토큰 버킷 레이트리밋, 공통 응답 envelope.
- 멱등 시드: 인용 출처가 있는 공개 참조 데이터 + 데모 테넌트(픽스처와 동일 수치).

### 6단계 — UI (항목 35~39)
- 앱 셸, 세션 프로바이더, 데모 모드 배너, 공용 데이터 표시·차트·액션 폼 컴포넌트.
- 18개 대시보드 화면 전부를 실제 저장소·엔진에 연결(조직, 마스터데이터, 활동자료, 배출 엔진, 계수 라이브러리, 분석, AI 엔진·로드맵·시뮬레이터·에이전트, MRV, 검증, 공시, 탄소금융, 보안, API 게이트웨이, 설정, 대시보드).
- 인증 화면 완성(비밀번호 찾기·재설정, 이메일 미확인 재발송, Supabase 미구성 안내)과 실제 랜딩 페이지.

## 4. 지금, 외부 자격증명 없이 동작하는 것

- `npm ci && npm run dev`만으로 18개 대시보드 화면 전체가 열립니다.
- 화면의 모든 수치(스코프별 배출량, 집약도, 불확실성 구간, 데이터 품질, SBTi 경로, 시나리오 투영, MACC와 NPV/IRR, 크레딧·ETS 포지션, 공시 완성도, MRV 커버리지, 이상치·예측)는 하드코딩이 아니라 실제 엔진이 픽스처를 계산한 값입니다.
- 12개 REST 엔드포인트와 API 키 인증·레이트리밋이 동작하며, 서술 텍스트는 결정론적으로 생성됩니다.
- 저장 동작만 `DEMO_MODE`로 거부되고, 그 사실을 배너와 오류 메시지가 한국어로 안내합니다.

## 5. 사용자가 직접 해야 하는 것

전부 **`docs/CIOS-직접-설정-가이드.docx`** 에 절차·명령·URL·예상 비용·완료 확인 방법과 함께 정리되어 있습니다.

1. 사전 준비 및 로컬 실행 2. Supabase 프로젝트·인증(OAuth 리다이렉트 URL 포함)·Storage 버킷
3. PostgreSQL 프로비저닝 + pgvector + `npx prisma migrate deploy` + `npm run db:seed`
4. OpenAI 키·모델·사용 한도 5. `FIELD_ENCRYPTION_KEY` 생성과 키 관리 6. Mapbox 토큰
7. Redis(선택) 8. 배포(Vercel 또는 Docker) + 도메인/DNS/SSL 9. 유료 배출계수 라이선스(ecoinvent, IEA, Sphera 등)
10. 법적·검증 절차(제3자 검증, ISO 14064-3, SBTi, CDP/CSRD/ISSB, 국내 배출권거래제)
11. 운영(백업·모니터링·감사 로그 보존·접근권한) 12. 미구현/외부 의존 기능 목록

**가장 먼저 할 일**: 개발 환경에 데이터베이스가 없어 모든 검증이 목(mock) Prisma 또는 데모 경로로 수행되었으므로, 데이터베이스를 준비한 직후 `npx prisma migrate deploy` → `npm run db:seed`를 실행해 주십시오.

## 6. 알려진 한계

CSV 일괄 등록의 커밋 액션, 알림 발송 채널, 한국어 UI 문구(메시지 테이블에 `ko` 컬럼은 준비됨), API 키별 개별 레이트리밋(스키마 컬럼 없음), 인터랙티브 지도, pgvector 시맨틱 검색, 검증 발견사항의 금액 전용 컬럼, 필드 암호화 키 회전 자동화, 감사 로그 아카이브 자동화 — 각 항목의 현재 상태와 필요한 조치는 가이드 문서 12절 표에 정리되어 있습니다. `Organization` 모델의 관계 필드 32개 문제는 검증된 스키마와 동결된 마이그레이션을 보존하기 위해 모델 구조를 바꾸지 않고, 저장소가 모듈별로 필요한 필드만 선택하도록 접근 패턴을 고정하는 방식으로 처리했습니다(README에 명시).

# Carbon Intelligence Operating System (CIOS)

A corporate carbon accounting and decarbonisation platform: GHG Protocol Scope 1/2/3 inventory,
data quality and uncertainty, SBTi target pathways, scenario simulation, MACC and investment
appraisal, carbon credit and ETS positions, disclosure reporting (CDP / ISSB / ESRS E1 / TCFD /
GRI / SASB), digital MRV and third-party verification support, plus a statistical AI layer with an
optional LLM narrative.

Next.js 16 (App Router) · React 19 · TypeScript · Prisma 6 (PostgreSQL, 148 models) ·
Supabase Auth · Tailwind 4 · Vitest.

> **직접 설정이 필요한 작업은 [`docs/CIOS-직접-설정-가이드.docx`](docs/CIOS-직접-설정-가이드.docx)에 한국어로 정리되어 있습니다.**
> Everything that needs your own accounts, credentials, budget or legal decisions — Supabase,
> PostgreSQL, OpenAI, Mapbox, Redis, deployment, commercial emission-factor licences, third-party
> verification and regulatory submissions — is documented step by step, with commands, URLs,
> expected cost and a "완료 확인 방법" (how to confirm completion) for each of its 12 sections.
> That document is generated by `npm run docs:setup-guide` from `scripts/generate-setup-guide.ts`.

## Quick start

```bash
npm ci                  # postinstall runs `prisma generate`
cp .env.example .env.local
npm run dev             # http://localhost:3000
```

With no environment variables set the application still runs — see [demo mode](#demo-mode).
To leave demo mode, provision a database and run:

```bash
npx prisma migrate deploy   # applies prisma/migrations/0_init (148 models)
npm run db:seed             # idempotent reference data + demo tenant
```

## Architecture

Layering is the load-bearing decision of this codebase: **all calculation lives in pure modules
that import no framework**, and persistence is a thin shell around them.

```
src/lib/core        Result/error types, number and reporting-period helpers      pure
src/lib/reference   GWP tables (AR4/5/6), unit registry, Scope 3 catalogue,      pure
                    disclosure framework catalogue
src/lib/domain      Every engine: units, GWP, factor resolution, Scope 1/2/3,    pure
                    aggregation and consolidation, uncertainty (seeded Monte
                    Carlo), data quality, rules, lineage, audit diffing, SBTi
                    targets, scenarios and carbon budgets, MACC/NPV/IRR,
                    roadmap, credits and ETS, disclosure mapping, MRV and
                    verification, statistical AI (anomaly/forecast/gap/
                    confidence)
src/lib/ai          LLM client interface + OpenAI and deterministic clients,     pure
                    explainable-AI assembly, agent runtime, tool registry, MCP
─────────────────────────────────────────────────────────────────────────────────────
src/lib/data        Prisma client, `withDb()` fallback, repositories, demo       Prisma
                    fixtures
src/lib/security    RBAC/ABAC authorisation, AES-256-GCM field crypto           Node crypto
src/lib/auth        Session resolution over Supabase Auth                       Supabase
src/lib/validation  zod schemas derived from the Prisma enum tuples             zod
src/lib/actions     14 server-action modules: auth re-check → validate →        Next
                    domain call → persist → audit trail
src/lib/api         API-key auth, token-bucket rate limiting, response envelope  Next
src/app/(dashboard) 18 pages, all reading real data through the repositories     Next
src/app/api/v1      12 REST endpoints (`Authorization: Bearer <apiKey>`)         Next
```

`src/lib/domain`, `src/lib/core`, `src/lib/reference` and `src/lib/ai` contain **zero** imports of
`@prisma/client`, `next/*` or `@supabase/*` — grep-verified, and the reason the engines can be
unit-tested at all in an environment with no database.

Other conventions:

- **Pages opt out of prerendering with `await connection()`**, not `export const dynamic`. The
  bundled Next 16 docs prefer it and `dynamic` is on the removal path. `connection()` is called in
  the page component, never in a repository, so repositories stay framework-free.
- **Monte Carlo uses a seeded PRNG** (`mulberry32`), never `Math.random()`, so uncertainty output
  is reproducible and therefore defensible in verification.
- **Emission and money math uses `number`** with explicit `roundTo` at presentation/persistence
  boundaries, matching the `Float` columns in the schema.
- **Sensitive fields are encrypted with AES-256-GCM** (`src/lib/security/field-crypto.ts`) keyed
  from `FIELD_ENCRYPTION_KEY`; audit diffs redact `passwordHash`, `mfaSecret` and `credentials`.
- **The database migration is a single offline-generated baseline.** `prisma/migrations/0_init` was
  produced with `prisma migrate diff --from-empty --to-schema-datamodel`, because `migrate dev`
  needs a live server. CI compares its digest against the schema.

### Documented deferral

The `Organization` model has 32 relation fields. Splitting it would mean rewriting a validated
148-model schema and invalidating the frozen baseline migration for no functional gain, so the
model is unchanged and the **access pattern** is what was fixed: repositories select narrow field
sets per module instead of eager-loading the organisation graph.

## Demo mode

Every repository read goes through `withDb(fn, fallback)` in `src/lib/data/db.ts`. When
`DATABASE_URL` is missing, a placeholder, or unreachable (`P1000`–`P1017`), the read returns a
bundled fixture dataset instead of failing the render, and a banner says so.

The important part: **fixtures are fed to the real engines.** Every number on screen is computed by
the same Scope 1/2/3, aggregation, uncertainty and quality code that runs in production — only
persistence is stubbed. Mutations refuse with `DEMO_MODE` rather than pretending to save. The seed
loads the identical dataset, so connecting a database does not change the figures, only makes them
writable.

To leave demo mode: set `DATABASE_URL` (and `DIRECT_URL`), run `npx prisma migrate deploy`, then
`npm run db:seed`. `/settings` shows the live configuration state of every dependency.

## Environment variables

`.env.example` is the authoritative list — each entry carries a comment stating exactly what
degrades without it, and `src/lib/env.test.ts` fails the build if a variable is read but
undocumented, or documented but unread.

| Variable | Required | Without it |
| --- | --- | --- |
| `DATABASE_URL` | yes | Demo mode: reads use fixtures (still computed), writes return `DEMO_MODE`. |
| `DIRECT_URL` | yes | `prisma migrate deploy` fails on providers that only allow DDL over a direct connection. |
| `NEXT_PUBLIC_SUPABASE_URL` | yes | No identity provider: demo administrator session, auth pages report the misconfiguration, no OAuth. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | yes | As above. |
| `OPENAI_API_KEY` | no | Narrative text is generated deterministically from calculation traces; every numeric result is unaffected. |
| `OPENAI_MODEL` / `OPENAI_BASE_URL` / `OPENAI_ORGANIZATION` / `OPENAI_TIMEOUT_MS` | no | Defaults: `gpt-4o-mini`, the public OpenAI endpoint, no organisation header, 60 s. |
| `FIELD_ENCRYPTION_KEY` | no | Registering a data source with credentials fails rather than storing plaintext. |
| `FIELD_ENCRYPTION_KEY_V2` | no | No key rotation is in progress; writes and reads both use `FIELD_ENCRYPTION_KEY` unchanged. |
| `MAPBOX_ACCESS_TOKEN` | no | The organisation page lists facility coordinates instead of a map. |
| `REDIS_URL` | no | Rate limiting stays in-process per instance. |
| `API_RATE_LIMIT_PER_MINUTE` | no | Default 60 requests/minute per API key (`rate:unlimited` scope, or the key's own `rateLimitPerMinute`, take precedence). |
| `AUDIT_RETENTION_DAYS` | no | Audit-log archival uses the documented 365-day default. |
| `CRON_SECRET` | no | `/api/cron/audit-archive` refuses every request — it fails closed, not open. |
| `RESEND_API_KEY` / `NOTIFICATION_EMAIL_FROM` | no | Rule-engine `notify` effects are logged server-side instead of emailed to the resolved recipients. |
| `SEED_ADMIN_PASSWORD` | no | The seed uses a documented default password and warns. |

## Testing

Vitest, `environment: 'node'` by default; component tests opt in per file with
`/** @vitest-environment jsdom */`. Tests co-locate as `*.test.ts` next to the source.

- **Domain engines** are tested against hand-computed values (e.g. IRR of `[-1000, 500, 500, 500]`
  ≈ 23.4 %, a 4.2 %/yr pathway reaching 42 % reduction over ten years, quadrature of 3 %/4 % ≈ 5 %),
  plus invariants: unit round-trips, seeded-PRNG reproducibility, rollups summing to the same
  grand total at every hierarchy level.
- **Repositories and actions** are tested with a mocked Prisma client and through the demo path,
  because no PostgreSQL server was reachable during development.
- **Pages** are tested in jsdom by asserting the rendered figures equal the engine output for the
  fixture dataset — that is how "the UI shows computed, not hardcoded, numbers" is enforced.
- **`scripts/generate-setup-guide.test.ts`** asserts the Korean document has all 12 sections with
  no empty body and packs to a real OOXML file.

Run a subset with a path filter: `npm test -- src/lib/domain/emissions`.

## Deployment

`Dockerfile` is a three-stage build producing a `node:22-alpine` image that runs the Next
standalone output as a non-root user on port 3000:

```bash
docker build -t cios:latest .
docker run --rm --env-file .env.local cios:latest npx prisma migrate deploy
docker run -d -p 3000:3000 --env-file .env.local cios:latest
```

Vercel works with the defaults; register the environment variables in the project settings and run
`prisma migrate deploy` as a separate release step, never as part of the build. Health check:
`GET /api/v1/health`. Full procedure, including domain/DNS/SSL, is section 8 of the Korean guide.

## Known gaps

Tracked honestly in section 12 of `docs/CIOS-직접-설정-가이드.docx`. The CSV import commit action,
per-API-key rate limits, a dedicated misstatement-amount column, notification delivery (Resend or
logged-only), field-encryption key rotation, and audit-log archival are all implemented in code —
what remains for each is provisioning the credential or infrastructure it needs (`RESEND_API_KEY`,
`CRON_SECRET` + a scheduler trigger, etc.), documented per variable in section 12's table. Still
genuinely open: full Korean UI copy (only the error-message keys and a locale toggle exist; success
messages and page copy stay English by design), pgvector semantic search (the embedding client and
schema exist, but the raw-SQL query and vector index need a live pgvector database to verify), the
interactive Mapbox map (works once a token is set, unverified without one), commercial factor
libraries, and third-party verification and regulatory submissions — the last two being work only
the operating organisation can do.

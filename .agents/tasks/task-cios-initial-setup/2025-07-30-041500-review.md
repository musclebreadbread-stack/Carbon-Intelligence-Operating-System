# Enterprise Carbon Management Platform Scaffold

This is a greenfield scaffold for an AI-native carbon management platform (CIOS), establishing the foundational architecture: a Next.js 16 App Router project with a 3,452-line Prisma schema covering 148 models across 18 modules, 22+ page routes with meaningful placeholder content, Supabase auth middleware, and a collapsible sidebar navigation. The approach is to build a comprehensive domain model first (all 15 Scope 3 categories, 7-level org hierarchy, rules engine, data lineage, explainable AI) and wire up the UI shell with static data, deferring real data fetching and business logic to future iterations. Watch for: middleware auth protection only covers `/dashboard` paths, leaving all other dashboard-group routes unprotected (confirmed); types in `src/types/index.ts` duplicate and diverge from the Prisma schema (confirmed); the root layout still carries default Next.js metadata (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The Prisma schema models the full GHG Protocol lifecycle with well-structured relations, appropriate cascading deletes, and composite indexes. It is internally consistent with one notable typo (`isManadatory`) and a security placeholder (`EncryptionKey.keyMaterial` stored as plain String) that needs flagging before real use.

The auth layer delegates entirely to Supabase. The middleware intercepts all non-static routes but only redirects unauthenticated users when the path starts with `/dashboard`. Since the `(dashboard)` route group doesn't add a URL prefix, paths like `/emission-engine`, `/ai-agents`, `/security` are exposed without authentication checks. This is a fail-open pattern.

The TypeScript types in `src/types/index.ts` define a parallel, simplified domain model that diverges from Prisma's generated types in field names, structure, and enum values. This will create confusion when real data flows are connected.

Login and register pages render full form UIs but have no form actions or Supabase auth calls, making the auth flow untestable end-to-end even with a running Supabase instance.

## Middleware auth protection scope

The middleware at `src/middleware.ts` runs on all non-static routes (via the matcher regex), but the actual protection logic in `src/lib/supabase/middleware.ts` only gates access for paths matching `request.nextUrl.pathname.startsWith("/dashboard")`:

```typescript
if (
  !user &&
  request.nextUrl.pathname.startsWith("/dashboard")
) {
  const url = request.nextUrl.clone();
  url.pathname = "/login";
  return NextResponse.redirect(url);
}
```

The `(dashboard)` route group is a Next.js organizational construct that does not add a URL prefix. The actual routes are `/emission-engine`, `/ai-agents`, `/security`, `/settings`, `/analytics`, etc. None of these start with `/dashboard` and none will trigger the redirect. Only the `/dashboard` page itself is protected.

This is a fail-open pattern: adding a new route to the `(dashboard)` group automatically exposes it without auth unless the middleware is updated. The fix is to either check against a list of public paths (login, register, root) and protect everything else, or to add a `/app` prefix to the route group.

## EncryptionKey plaintext storage

The `EncryptionKey` model stores `keyMaterial` as a plain `String` field. If this schema is ever used with real key material, this is a critical security concern. A comment flagging this as "schema placeholder, real implementation must use a KMS" would prevent future misuse.

## Parallel type system divergence

`src/types/index.ts` defines 164 lines of manual TypeScript interfaces that overlap with but diverge from the Prisma schema:

- `Organization` includes `slug` and `type` fields that don't exist in the Prisma model
- `User` has a `role: UserRole` field (simple enum string) while Prisma uses a many-to-many `UserRole` join table with full RBAC
- `EmissionRecord` doesn't map to any single Prisma model (it's a blend of `EmissionResult` and `ActivityData`)
- `EmissionScope` uses `"scope1" | "scope2" | "scope3"` while Prisma uses `SCOPE_1 | SCOPE_2_LOCATION | SCOPE_2_MARKET | SCOPE_3`

These manual types are useful as API response DTOs but should be explicitly labeled as presentation models, not confused with the persistence layer.

## Login/register forms without actions

The login page renders Google SSO, Microsoft SSO, and email/password options, but none are connected to Supabase auth. The inputs have no `name` attributes, no form `action`, and no client-side handlers. Since the middleware protection depends on `supabase.auth.getUser()` returning a user, the entire authenticated experience is untestable without manually setting auth cookies.
